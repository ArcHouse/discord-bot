# Надёжность игровой рассылки

Подготовлено на основе master `25e4cda46d490f3cbd45601992089698b6b8e277`. Рабочий Render и Discord не изменены.

## Подтверждённые проблемы исходного кода

- `setInterval(1 час)` после Discord ready не привязан к минуте 00. `getHours()` использует часовой пояс процесса, а не явно Москву. После сна процесс начинает отсчёт заново и может не дождаться первого запуска.
- Локальная история `published-news.json` исчезает при рестартах/сне Render Free. Пометки добавлялись до успешной отправки; ошибка send подавлялась, а вызывающий endpoint отвечал OK.
- Первый канал с подходящим названием выбирался без проверки дубликатов. Глобальная история могла подавлять отправку в другой сервер.
- До 10 карточек по 500 символов плюс заголовки/поля могли превысить общий лимит Discord 6000 символов. Длина заголовка не ограничивалась 256 символами.
- Прямой вызов новостного HTTP endpoint не имел авторизации. `/healthcheck` подтверждает только работу HTTP, а не Discord или рассылки.
- Ключ DeepL передавался в URL. Ошибки могли выводить URL запроса в журнал.

Эти ошибки подтверждены кодом, но НЕ доказывают причину остановки рабочего сервиса. Дата статьи 12 августа в карточке не является датой отправки сообщения.

## Что изменено

- Расписание 08:00, 14:00, 20:00 с явным `NEWS_TIMEZONE` (по умолчанию `Europe/Moscow`). Проверка раз в минуту, один запуск последнего слота сегодня после пробуждения; без пачки всех пропущенных выпусков. Ошибки повторяются на следующей проверке. Во сне процесс по-прежнему ничего не выполняет.
- Источник истории — сообщения этого бота в целевом Discord-канале, а не временный файл. Проверяются права ViewChannel, SendMessages, EmbedLinks, ReadMessageHistory. Недоступная история останавливает отправку. Проверяется до 500 сообщений, до выхода за окно свежести.
- Только статьи за последние 72 часа с корректной датой и http(s) ссылкой; дедупликация по URL отдельно для каждого канала. Удалённые сообщения больше не считаются опубликованными. Если 500 сообщений не покрывают 72 часа, нужна отдельная новостная лента. Изменённые tracking URL могут считаться разными статьями; семантической дедупликации разных источников нет.
- Совпадающие одновременные вызовы в одном процессе объединяются. Nonce Discord дополнительно защищает повтор одного пакета в течение нескольких минут. Это не распределённая блокировка: эксплуатировать один экземпляр бота, не два одновременно.
- Неоднозначный выбор канала останавливается с `NEWS_CHANNEL_AMBIGUOUS`. `NEWS_CHANNEL_ID` выбирает один конкретный канал и его сервер.
- Общий лимит карточек 6000 символов и 10 embeds соблюдается; отдельные заголовки обрезаются. Формат одного сообщения с карточками и флагом 4096 сохранён.
- RSS загружаются параллельно с таймаутом 10 секунд на источник. Отказ одного источника не блокирует остальные, отказ всех возвращает ошибку.
- DeepL использует POST с JSON и ключом в Authorization; Google и исходный текст остаются fallback. Ключи и сырой текст ошибок перевода не выводятся.
- `/ready` показывает состояние Discord и попытки рассылки с момента запуска; lastSent означает успешный send в этом процессе, а не дату последней публикации за всю историю. HTTP 200 на `/ready` сам по себе не подтверждает успешную рассылку: смотреть `news.lastResult` и журнал. Список каналов и секреты не публикуются.
- `NEWS_CRON_SECRET` позволяет закрыть существующий news endpoint Bearer-ключом. Пока переменная не задана, GET/POST сохраняют совместимость со старым cron. Перед production рекомендуется настроить ключ одновременно в Render и cron; он не должен быть в URL, репозитории или чате.
- `NEWS_PRODUCTION_ENABLED=false` блокирует основную рассылку из всех точек входа и внутренний таймер. Закрытый тест при этом работает.

## Закрытый тест

После установки этой версии владелец сервера выполняет `<PREFIX>newstest` (обычно `!newstest`). Другие пользователи, включая обычного администратора, не могут запускать эту команду.

Команда сначала ищет `мой-для-тестов` (включая эмодзи в названии) или `zohan-news-test`. Один подходящий закрытый текстовый канал переиспользуется. Если найдено несколько или разрешён просмотр другой роли/участнику, отправка останавливается; права существующего канала не меняются.

Если канала нет, создаётся `zohan-news-test` без категории и наследования прав: everyone запрещён ViewChannel, доступ разрешён владельцу и боту. Одновременные команды в одном процессе не создают дубликат. После создания права повторно проверяются; тест отправляется только туда. Дедупликация и диагностика основной рассылки не затрагиваются.

Discord owner и участники с Administrator могут обходить ограничения канала. Обещать невидимость от администраторов нельзя. Для создания канала боту нужен ManageChannels; для повторного использования он не нужен. Команда не запускает setupnews и ничего не удаляет.

## Порядок проверки и выкладки

1. Проверить diff и выполнить `node --test`, `node --check index.js`. Зависимости не добавлены. Полный запуск требует исходных npm-зависимостей и Render env, секреты сюда не копировать.
2. До установки версии в Render задать `NEWS_PRODUCTION_ENABLED=false`, чтобы новая версия не публиковала в основной канал после запуска. Изменение env может перезапустить текущую версию; на согласованное окно проверки остановить внешний новостной cron. Не запускать два экземпляра с одним токеном одновременно.
3. Выложить выбранную проверенную ветку/коммит вручную. Не пушить непроверенное в master: там может работать auto-deploy.
4. Выполнить `!newstest` от владельца. Проверить закрытый канал, перевод, картинки, повторный тест без дублей, журналы `[news]` и `[news-test]`. Если канал уже существует с неподходящими правами, сначала проверить его настройки вручную.
5. Указать `NEWS_CHANNEL_ID` нужного основного канала и `NEWS_TIMEZONE=Europe/Moscow`. ID не секрет. По текущему репозиторию нельзя узнать, какой из двух похожих каналов на реальном сервере является основным.
6. Для внешнего cron задать отдельный случайный `NEWS_CRON_SECRET` в Render и `Authorization: Bearer …` в cron. В URL секрет не добавлять. Затем вернуть `NEWS_PRODUCTION_ENABLED=true` только после проверки.
7. Выбрать одну стратегию: постоянно работающий сервис для внутреннего расписания или внешний cron, который будит Free web service. Для внешнего cron практичный исходный график — `08:00/14:00/20:00 Europe/Moscow`, с предварительным GET `/healthcheck` за несколько минут и повтором новостного запроса при сетевом/5xx сбое. Healthcheck не запускает выпуск напрямую. Учесть, что пробуждение старой/включённой версии может впоследствии запустить внутренний таймер. Не трактовать успешный healthcheck как отправку новостей.
8. Внешний вызов `/post/gaming-news` остаётся принудительной проверкой вне расписания; частый healthcheck допустим для статуса, но частый вызов news endpoint способен публиковать новые RSS при каждом обращении. Никогда не использовать его как uptime-пинг. Увеличить HTTP timeout cron с учётом холодного запуска и последовательных переводов (в худшем случае несколько минут). Повторы объединяются только пока выполняется один процесс.

Для точного времени последней публикации нужны timestamp/ID сообщения Discord или строка send в рабочих журналах. Текущего доступа к сообщениям Discord, настройкам cron и Render env нет; работоспособность живых RSS и HTTP из среды проверки не подтверждена из-за ограничений доступа/DNS. Локальные тесты используют контролируемые ответы и не отправляют сообщения в Discord.

## Первичные источники и сравнение практик

Вместо непроверяемого сравнения с чужими серверами применены документированные ограничения платформ:

- Render: сон после 15 минут без входящего трафика, потеря файлов при рестарте/сне; внутренний таймер не заменяет внешний планировщик: https://render.com/docs/free
- Discord: лимиты 10 embeds/6000 символов, nonce/enforce_nonce, разрешения чтения истории: https://docs.discord.com/developers/resources/message
- Discord: owner/Administrator обходят channel overwrites: https://docs.discord.com/developers/topics/permissions
- rss-parser: таймауты, HTTP options, поведение parseURL: https://github.com/rbren/rss-parser
- DeepL: POST /v2/translate и авторизация заголовком: https://developers.deepl.com/api-reference/translate/request-translation

Источники RSS и назначение Telegram/LoL оставлены прежними; перевод остаётся общей функцией и протестирован с fallback.
